1. **Test isolation:** `src/lib/server/testing/`, `playwright.config.ts`, `scripts/migrate-test-db.ts`, `.env.example`, and CI now require `TEST_DATABASE_URL`, preserve explicit shell selection, and isolate the browser app's database, auth secret, and email settings. Check that no path falls back to an app database, imports all of `.env.local`, reuses a live server, or sends real email.
2. **Authentication:** `create-auth.ts` contains Better Auth configuration; `auth.ts` wires runtime services. Pending OTPs are encrypted while resend reuse remains. Unsupported OTP purposes and unused routes are restricted, origin/CSRF checks stay enabled in tests, and the supported pg adapter transaction option is enabled. Verify normalization, open signup, expiry, attempt limits, concurrent consumption/replay, cookies/hosts, shared database rate limits, and integration through the real HTTP handler. These are supported Better Auth features, not a replacement auth system.
3. **Email and secret boundaries:** `email.ts` requires a key on hosted Preview/Production and sanitizes returned provider errors. Delivery remains awaited with no speculative retry/idempotency key that would suppress legitimate resends. Check server-only imports, logs/errors, and client artifacts. A successful build alone does not enforce the runtime email guard or prove delivery.
4. **Database availability:** `db/client.ts` handles idle pool errors without sensitive payloads and bounds connection/acquisition waits. Confirm pg/Vercel lifecycle and TLS assumptions. The timeout is not a query timeout and does not fix the unresolved Drizzle driver edge.
5. **Server validation and identity:** `/seen/+page.server.ts` returns deliberate errors for malformed forms and the specific missing-movie FK failure, propagates unexpected failures, and bounds IDs/page arithmetic. 6. **Client state and recovery:** the sign-in page locks conflicting controls during requests, focuses step transitions, and uses POST before hydration. Reserved action keys are removed from form/remembered redirect URLs while filters remain. Review delayed/failed requests, concurrent refreshes, stale URLs, and retry behavior; no-JavaScript functional login was not added.
7. **Catalog boundaries:** TMDB schemas validate SQL/domain bounds, dates and CDN filenames; GETs have bounded attempts/timeouts/Retry-After. Details IDs must match requests. Genre links are deduplicated; `save-catalog.ts` handles empty links and atomic upsert/replacement/rollback. The Development seed orchestrates bounded requests and rejects known hosted environments. Check compatibility with legitimate provider placeholders; provider mocks are not proof of real TMDB responses.
8. **Regression coverage and cleanup:** added real PostgreSQL authentication, rate-limit, query/isolation, concurrency, rollback and catalog tests, mocked provider failures, Chromium component recovery tests, and full browser journeys. Check installed types/tagged sources rather than Kit 2 or newer examples. Two Better Auth lockfile range declarations were normalized without changing their resolved 1.7.7 versions.
